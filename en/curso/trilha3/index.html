🛠️ Anatomy of grill-me’s SKILL.md

From frontmatter to closing the loop: what each part of the file does, why the simple version gained checkpointing, and how the output feeds back into your system.

0 of 8 read0%
What it is:

The top of the file shows name e description. The description lists the triggers—the situations in which the model should load the skill.

Why learn:

A poor description means a skill that never triggers, or triggers at the wrong time. It's the entry point.

Key concepts:

name · description = triggers · activation at the right time.

What it is:

The original skill is a very short prompt: interview relentlessly, follow every branch, give the recommended answer, ask one question at a time, and explore the codebase instead of asking.

Why learn:

Show that a powerful skill can be just a few carefully chosen sentences.

Key concepts:

Minimalism · prompt as a skill · authorship.

What it is:

After EACH answer, before the next question, append to the capture file. Never in batches. Fix earlier entries if something changes.

Why learn:

It’s the rule that separates the practical version from the simple one—and the one that best protects against context loss.

Key concepts:

Non-negotiable · one at a time · correct the past.

What it is:

Before asking: get the date, create brainstorms/ if it doesn’t exist, create the file with a header (title/date/goal/Open flags) and say where you’re saving it.

Why learn:

The right setup ensures a predictable home and keeps everything from being scattered across projects.

Key concepts:

Predictable folder · create it first · say where it is.

What it is:

The file has 4 sections: header; Summary/key decisions (ongoing synthesis); Q&A log (Asked, Captured in his own words, Flags); Open flags (item → who answers).

Why learn:

The fixed structure makes brainstorming traceable and easy to turn into a deliverable later.

Key concepts:

4 blocks · living synthesis · traceable.

What it is:

The simple version (Pocock) works, but during long interviews the context fills up and the model forgets. This variation writes to disk after every answer—longer, more robust.

Why learn:

Understanding the trade-off helps you decide how much ceremony your case calls for.

Key concepts:

Trade-off · robustness · the context fills up.

What it is:

A skill doesn’t have to be complex automation. It can just be a prompt you’re tired of typing every time. grill-me proves it.

Why learn:

Lowers the barrier: any instruction you repeat is a candidate to become a skill.

Key concepts:

Skill ≠ automation · reuse · capture what’s repeatable.

What it is:

In the end, grill-me realizes there’s a related guide/skill with a nuance that isn’t there and offers to update both — the output feeds back into your OS.

Why learn:

It’s what turns a good conversation into a lasting improvement to the system.

Key concepts:

Feed the OS · output → skill/doc · closed loop.
